# Pellets Water Heater - CLAUDE.md

## Project Overview
A native Android app (min SDK 24) for monitoring and logging temperature data from a pellets water heater system. Built with Kotlin 2.0, Jetpack Compose, Koin DI, and WorkManager.

**Key Features:**
- **F1 - Metadata Parsing**: Fetches/merges JSON metadata from server, converts raw sensor values
- **F2 - Logging**: CSV logging with dynamic headers, 5MB rotation, FileProvider sharing
- **F3 - UI (In Progress)**: Compose UI with navigation drawer (Data, Value Selection, Logs, Settings, About, Donate screens) + Glance widget

## Architecture

```
├── ui/                    # Compose screens (11 files)

│   ├── dialog/            # CodeEditorDialog, ConfirmDeleteDialog
│   ├── misc/              # UiEvent, UiState, ComposeUtils
│   └── theme/             # Material3 theme

│   ├── ContextProvider.kt # File ops abstraction
│   ├── MetadataUtils.kt   # JSON parsing/merging with kotlinx.serialization
│   ├── ValueConverter.kt  # Raw → logical value conversion
│   ├── TemperatureLogger.kt # CSV logging interface + impl
│   ├── Logger.kt          # ILogger interface + Android/console impl
│   └── TemperatureUtils.kt # WorkManager, SharedPrefs, URL handling
├── viewmodel/             # TemperatureViewModelNew.kt (main VM)
├── PelletsWaterHeaterApplication.kt
├── TemperatureWorker.kt   # WorkManager CoroutineWorker
├── TemperatureWidget.kt   # Glance AppWidget
├── SettingsViewModel.kt   # Settings + logging service control
├── NetworkAccess.kt       # OkHttp wrapper
└── MainActivity.kt        # Compose Navigation + ModalNavigationDrawer
```

### Data Flow
```
Server JSON → MetadataUtils.parseServerJson() → MetadataJson (sections → fields)
User JSON → MetadataUtils.parseUserJson() → mergeMetadata() → prioritized user fields
Raw values → ValueConverter.convert() → ConvertedValue(logical, name, unit)
Selections (SharedPreferences) → filter convertedValues for UI/Widget/Logging
TemperatureWorker (10min periodic + manual) → fetchValues() → updateValues() → logValues()
```

### Key Data Models
- **MetadataJson**: `sections: Map<String, Map<String, MetadataEntry>>`, `error: String?`
- **MetadataEntry**: sealed class → `MetadataField(val, unit, factor, offset, name, format, min, max, decimals)` or `MetadataLabel(label)`
- **ConvertedValue**: `logical: String`, `name: String`, `unit: String?`
- **Selection**: `key, log, widget, showData, showSectionName` (persisted in SharedPreferences)

## Important Patterns

### Koin DI
```kotlin
// AppModule.kt provides:
single<ContextProvider> { AndroidContextProvider(get()) }
single<ILogger> { Logger }
single { OkHttpClient() }
single<TemperatureLogger> { TemperatureLoggerCsvImpl(get(), get()) }
single { TemperatureViewModelNew(get(), get(), get(), get()) }
```

### StateFlow in ViewModel
```kotlin
private val _metadata = MutableStateFlow<MetadataJson?>(null)
val metadata: StateFlow<MetadataJson?> = _metadata.asStateFlow()

// Compose collects via: viewModel.metadata.collectAsState()
```

### Worker + ViewModel Communication
- `TemperatureWorker` injects `TemperatureViewModelNew` via Koin
- Calls `viewModel.fetchValues(url, caller, doLogging)` on background thread
- Updates widget via `TemperatureWidget().forceUpdateAll(context)`

## Common Tasks

### Add a new metadata field
1. Server returns it in JSON → automatically parsed by `MetadataJsonSerializer`
2. User can override via Settings → Edit Metadata JSON
3. Appears in ValueSelectionScreen for log/widget/showData checkboxes

### Modify CSV format
Edit `TemperatureLoggerCsvImpl.writeHeaders()` and `buildCsvRow()`

### Change widget layout
Edit `TemperatureWidget.TemperatureWidgetContent()` Composable

### Add a new screen
1. Create Composable in `ui/`
2. Add route in `MainActivity.AppNavigation()`
3. Add item in `DrawerContent.kt`

## Development Tools

### Eclipse JDT Language Server (Java)
Installed at `~/.local/share/jdtls` (v1.53.0 milestone). Launcher script at `~/.local/bin/jdtls`.

**Configuration:**
- Uses SDKMAN Java 21 (Corretto 21.0.13.0+10)
- Uses `config_linux` configuration
- Added to PATH via `~/.bashrc`

**Usage:**
```bash
jdtls                    # Start JDT LS
jdtls --help             # Show help
```

**For LSP clients (e.g., nvim-lspconfig, vscode):**
```json
{
  "cmd": ["/home/pi/.local/bin/jdtls"],
  "root_dir": "workspaceFolder"
}
```

### Kotlin Language Server (Kotlin)
Installed at `~/.local/share/kotlin-lsp/kotlin-server-263.7084.0/` (v263.7084.0 EAP). Launcher script at `~/.local/bin/kotlin-lsp`.

**Configuration:**
- Uses bundled JetBrains Runtime (JBR) Java 25
- Runs in stdio mode for LSP clients

**Usage:**
```bash
kotlin-lsp               # Start Kotlin LSP (stdio mode)
kotlin-lsp --help        # Show help (via intellij-server)
```

**For LSP clients (e.g., nvim-lspconfig, vscode):**
```json
{
  "cmd": ["/home/pi/.local/bin/kotlin-lsp"],
  "root_dir": "workspaceFolder"
}
```

**Note:** Kotlin LSP stdio mode may have issues responding to initialize requests. Socket mode (`intellij-server --socket 127.0.0.1:9999`) works reliably.
